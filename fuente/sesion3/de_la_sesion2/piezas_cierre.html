5

Una base de datos es catálogo + archivos

Tablas con nombre y tipos, en Parquet y particionadas: cualquiera las consulta con SQL y cada consulta lee solo lo que necesita.

6

Confiable = verificado

Cuatro caminos, el mismo total; controles que dan cero; seudónimos con sal. La confianza se demuestra con evidencia ejecutable.

  • Base de datos. En la base guadua: una tabla oro con las ventas mensuales por ciudad y categoría, particionada por mes y cargada de forma repetible (ejecutar la carga dos veces no debe duplicar filas), y cuatro consultas SQL que respondan preguntas de la gerencia (al menos una con JOIN y una con ventana). Para una de ellas, el EXPLAIN que muestre la poda de particiones, con su interpretación.
  • Controles (CR1 y CR3). Al menos un control de cada tipo, ejecutable y con su resultado: seguridad (una tabla o vista para analistas con el cliente seudonimizado con hash y sal; la sal se lee de una variable de entorno o del panel Secretos de Colab y no se escribe en el notebook), eficiencia (bytes leídos por una consulta en CSV frente a Parquet), coherencia (una batería de reglas que den cero) y correlación (una relación medida e interpretada con sus límites). Incluyan en el informe un esquema de qué control de seguridad protege el dato en cada fase (HDFS crudo, bronce, plata, oro) y por qué.
    • Catálogo (metastore)Registro de bases de datos, tablas, columnas y ubicación de sus archivos. Lago de datos / lakehouse (data lake / lakehouse)Archivos abiertos, como Parquet, más un catálogo que les da forma de tablas / un lago al que se agregan transacciones, historial de versiones y control de cambios (Delta Lake, Apache Iceberg). Tabla de hechos / dimensión (fact / dimension table)Una fila por evento medible, con llaves y medidas (ventas) / los atributos descriptivos de una entidad (productos). Juntas forman un modelo en estrella (star schema). Tabla administrada / externa (managed / external table)Sus archivos los maneja Spark y DROP TABLE los borra / solo apunta a archivos de otros, que DROP TABLE no toca. DDL (data definition language)Parte de SQL que define estructuras: CREATE, ALTER, DROP. Partición de tabla (table partition)Carpeta con las filas que comparten el valor de una columna —mes=2025-06—, creada con partitionBy. Modos de escritura (save modes)Qué hace Spark si la tabla ya existe: overwrite la reemplaza, append agrega filas, errorifexists falla (por defecto), ignore no hace nada. Idempotencia (idempotency)Ejecutar una o varias veces deja el mismo resultado. Plan de ejecución (execution plan)Los pasos con que Spark va a resolver una consulta; EXPLAIN lo muestra sin ejecutarla. Poda de particiones (partition pruning)Leer solo las carpetas (particiones de tabla) que cumplen el filtro. CTE (common table expression)Consulta intermedia con nombre (WITH … AS) que se usa como si fuera una tabla. Seudonimización (pseudonymisation)Reemplazar un identificador por un código que no revela la identidad sin una información adicional guardada aparte. Los datos seudonimizados siguen siendo datos personales. Sal (salt)Valor que se une al identificador antes de calcular el hash. Si es secreto y se guarda fuera del código y de los datos, nadie puede recalcular el seudónimo; en rigor funciona entonces como una clave, y la práctica recomendada es un hash con clave (HMAC). Anonimización (anonymisation)Transformar los datos de forma irreversible para que la persona ya no sea identificable; solo así dejan de ser datos personales. Correlación de Pearson (Pearson correlation)Grado en que dos variables varían juntas en línea recta, de −1 a +1. No dice cuál causa a cuál.
